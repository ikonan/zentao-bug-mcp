# 修复禅道 Bug

## 概述

配合 zentao-bug-mcp 使用：丢一个禅道 bug 链接，按固定流程完成 取 bug → 看截图 → 定位修复 → 验证 → 汇报。

## 硬约束

- **只读禅道**：不执行任何写操作，不自动"解决/关闭/指派" bug，状态变更由用户在禅道里自行操作。
- **标题完整保留**：复述和汇报中 bug 标题必须逐字保留，不截断、不改写、不翻译——标题里常含模块名、版本号等关键信息。
- **只走 MCP**：bug 数据和附件一律通过 `zentao_get_bug` 获取，不自己拼 API URL、不爬网页、不用 cookie 方式下载文件。

## 工作流

### 1. 取 bug

把用户给的链接或 ID **原样**传给 `zentao_get_bug`（默认下载附件和评论动态；只关心截图时可传 `downloadAttachments: false`，只看步骤不看评论时可传 `includeComments: false`）。

错误处理：

| 报错 | 处理 |
|---|---|
| 工具不存在 / MCP 未配置 | 给出下方配置片段让用户配好后重试，停止流程 |
| 链接主机与 ZENTAO_BASE_URL 不一致 | 提示用户核对 env 中的 `ZENTAO_BASE_URL`；不要绕过（这是凭据安全限制） |
| 登录失败 / API 不可用 / 连不上 | 按报错提示用户检查账号密码、禅道 REST API 开关、内网/VPN |
| 个别图片下载失败 | 照常继续，最终汇报中注明缺哪张图 |

MCP 配置片段（未配置时给用户）：

```json
{
  "mcpServers": {
    "zentao": {
      "command": "npx",
      "args": ["-y", "zentao-bug-mcp"],
      "env": {
        "ZENTAO_BASE_URL": "http://your-zentao-host/zentao",
        "ZENTAO_ACCOUNT": "账号",
        "ZENTAO_PASSWORD": "密码"
      }
    }
  }
}
```

### 2. 看截图

工具返回 Markdown 报告，含"重现步骤"、"评论与动态"、"附件"、"本地文件"小节。**对"本地文件"里的每张图片用 Read 工具查看，不许跳过**——截图里的 UI 文案、报错信息、异常界面是定位代码的最强线索。日志类附件（.txt/.log）也要读。

**评论区必须读**："评论与动态"时间线里，激活/评论动态常补充"没改彻底"的遗留问题和新的复现截图——被激活过的 bug 尤其要逐条看评论文字和其中的截图，修复范围以最新评论为准。

### 3. 复述 bug

开始修之前先向用户复述一行：`Bug #{id}: {完整标题}`，附严重程度和关键重现步骤，确认理解无误（简单明确的 bug 不必等用户确认，直接继续）。

### 4. 定位并修复

- 用截图中的 UI 文案、报错关键词、步骤里的功能名搜索代码。
- 先找根因再改，最小改动修复，不顺手重构、不加无关功能。

### 5. 验证

- 跑项目的构建和相关测试；有对应测试就先跑红再修绿。
- UI 改动尽量实际运行验证；无法运行验证时明确告知用户"未实际验证 UI"。

### 6. 汇报

按此结构汇报：

```
Bug #{id}: {完整标题}
根因：…
改动：{文件列表 + 一句话说明}
验证：{构建/测试/运行结果}
```

有图片下载失败或未能验证的部分，如实注明。不修改禅道上的 bug 状态。
